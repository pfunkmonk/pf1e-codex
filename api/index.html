PF1e Codex API

Read-only JSON for all 40,077 entries in the Codex — classes, spells, feats, monsters, items, rules and more. No key, no sign-up, and CORS is open, so it works from a browser as well as a script.

Data release 81 · base URL https://codex.pipsprojects.com/api/v1

Endpoints

PathReturns
/api/v1/index.jsonManifest: totals, every bucket and its categories with counts.
/api/v1/{bucket}.jsonEvery entry in a bucket — id, name, category, source, facets and a short snippet. No body.
/api/v1/names.jsonJust [id, name, bucket] for all entries — one small file for looking a name up across buckets.
/api/v1/entries/{id}.jsonOne entry in full: the body text, plus any tables.

Examples

curl https://codex.pipsprojects.com/api/v1/index.json

# find an entry by name, then fetch it
curl -s https://codex.pipsprojects.com/api/v1/names.json | jq '.rows[] | select(.[1]=="Fireball")'
curl -s https://codex.pipsprojects.com/api/v1/entries/6523ad88412e172a.json
const list = await (await fetch("https://codex.pipsprojects.com/api/v1/spells.json")).json();
const hit  = list.entries.find(e => e.name === "Fireball");
const full = await (await fetch("https://codex.pipsprojects.com/api/v1/entries/" + hit.id + ".json")).json();
console.log(full.body);

body is the entry text exactly as the Codex stores it. Its layout is not uniform — some bodies begin with the entry’s name, many with a Source line, and many with something carried over from the original page (a breadcrumb like Rules Index | GM Screen, a subtitle, or intro prose); the manifest’s totals.bodyLayout has the measured split. Use the structured fields (name, source, book, facets) rather than parsing the first lines of the body. facets varies by bucket (spells carry sch school, lv level per class and so on; most carry bk, the book). Entries with tables — the Summon Monster spells, class progressions — also have a tables array of { headerRow, rows }; when headerRow is true the first row is the header. links.web opens the same entry in the app.

Things to know

  • IDs are opaque. They stay put as long as the underlying data is not rebuilt. Store the id together with the name, and re-resolve through names.json if a lookup ever misses.
  • Versioning. dataVersion changes with every data release. Responses may be cached for a few minutes.
  • Same view as the site. A few scraped index pages the site hides from browse and search are hidden here too.
  • Be kind. It is static files on a CDN, so there is no rate limit — but bulk-pulling every entry is ~40k requests; fetch the bucket lists and only the entries you need.
